# SEO-решение: страница /gde-poest

Проект: lovelifestyle.ru — апарт-отель «Стиль Жизни», Алушта.
Дата: 2026-10-10.

---

## 1. Индексируем или noindex?

### Решение: noindex + follow: false

### Аргументы за noindex

**Интент страницы не совпадает с интентом поиска.**
Страница — утилита для гостя, который уже забронировал. Пользователь в Яндексе/Google,
набирающий «где поесть в алуште» или «кафе алушта», ищет ресторан, а не апарт-отель.
Конверсии в бронь от этого трафика практически нет.

**Тонкий контент = риск «малоценной страницы».**
Сайт уже получил сигналы Яндекса о малоценности (карточки апартаментов).
Страница с 6 карточками сторонних заведений (5 кафе + 1 супермаркет) —
классическая «тонкая» страница по критериям Яндекса: мало уникального текста,
основной контент — чужие данные (телефоны, адреса, ссылки).

**Контент о чужих бизнесах.**
Страница перечисляет конкурирующие заведения. С точки зрения Яндекса это не редакционный
контент сайта отеля — это агрегатор ссылок. Такие страницы не ранжируются на коммерческом сайте
и тянут вниз общую оценку ресурса.

**Нет ни одного целевого ключа в семантическом ядре.**
`spec/semantic-core.md` намеренно исключает информационный кластер «отдых в алуште»,
«достопримечательности», «где поесть» — весь топ воронки. Включение этой страницы
в индекс создаёт торчащий информационный URL среди коммерческих посадочных страниц
и размывает тематическую когерентность домена.

**Данные Wordstat не сняты, числа не приводим.**
Playwright под аккаунтом Олега в этой сессии недоступен. Значит, реальной частотности
по кластерам «где поесть в алуште», «кафе алушта», «рестораны алушта» нет.
Без цифр — нет основания включать кластер. Когда будут цифры из Вордстата —
решение можно пересмотреть при условии, что частотность окажется значимой (>500 показов)
и будет чёткая воронка к бронированию.

### Аргументы за индексирование (и почему они слабее)

- «Страница могла бы привлекать туристов, планирующих отдых» — верно, но
  планировщики ищут рестораны на картах и TripAdvisor, а не на сайте конкретного отеля.
- «Лишний URL в брендовой выдаче не помешает» — в данном случае мешает:
  «малоценные страницы» в индексе снижают краулинговый бюджет, нужный
  /apartments и посадочным.

### Итог

`robots: { index: false, follow: false }` — страница работает как закрытая утилита.
Открытость для поиска не добавляет ей ценности и несёт конкретный риск для домена.

**Важно:** noindex не ломает og-теги. Telegram, WhatsApp и VK читают og напрямую
из HTML при рендеринге превью ссылки — до того как бот смотрит на robots.
og-картинка и мета нужны в полном объёме, только для шаринга.

## 2. Ядро запросов

Страница не индексируется, поэтому целевого ядра нет.
Семантику для кластера «кафе/рестораны Алушта» целесообразно снять через Playwright/Вордстат
отдельно — только если принято решение переключить страницу на index:true.

Кластеры для ориентира (без реальных цифр, не использовать как факты):
- «где поесть в алуште» — информационный, верх воронки
- «кафе алушта» — микс информационного и навигационного
- «рестораны алушта» — аналогично
- «доставка еды алушта» — потенциально ценнее, более транзакционный

```typescript

  /*

   * Поэтому: noindex, но og-теги в полном объёме для шаринга.
   * og:image — JPEG 1200×630, не WebP (Telegram/WhatsApp/VK не показывают WebP).

  const title = 'Где поесть рядом со «Стилем Жизни» | Алушта';
```

Длина title: 46 символов (до лимита 70 запас есть).
Длина description: 147 символов (в пределах 160).

## 4. Schema.org

### Что размечать и почему нельзя LocalBusiness для чужих заведений

`LocalBusiness` на странице отеля для сторонних кафе — ошибка.
Это означало бы, что кофейня «Встреча», ресторан «Старый город» и другие
являются бизнесами, управляемыми lovelifestyle.ru. Яндекс и Google
используют эти данные для карточек в поиске: неправильная привязка даст
спорные сигналы и может привести к жалобам владельцев.

### Правильная разметка: BreadcrumbList + ItemList

`ItemList` перечисляет заведения как рекомендуемые объекты — без претензии
на управление данными. `Restaurant` внутри `ItemList` — корректный паттерн,
аналогичный редакционному гиду.

Поскольку страница noindex, эта разметка не нужна для SEO-сниппетов.
Она нужна только для семантической корректности и на случай пересмотра решения.

## 5. og-картинка: public/og-gde-poest.jpg

### Нужна ли?

Да, обязательно. Основной сценарий — ссылка в Telegram/WhatsApp.
Без og:image мессенджер покажет пустую карточку или случайный кадр со страницы.

### Из какого исходника резать

Исходник: `public/images/gde-poest/endorphin-interior.webp` (~960x1280, вертикальный).

Интерьер: мурал с танцующей парой, деревянные балки, бежевые диваны,
панорамное окно в зелень. Атмосферный кадр, передаёт уют — лучше,
чем снимок с напитком (`endorphin-coffee.webp`), который слишком предметный
для превью-карточки.

### Инструкция по нарезке (для дизайнера/фронтенда)

Исходник вертикальный 960×1280. Нужен горизонтальный 1200×630.

Алгоритм:
1. Масштабируй исходник по ширине до 1200px (результат: 1200×1600).
2. Вырежи из центра полосу 1200×630 (offset по Y: примерно 300px сверху — там
   самая насыщенная часть кадра с муралом и диванами).
3. Сохрани как JPEG, quality 85–90, sRGB.
4. Положи в `public/og-gde-poest.jpg`.

Итоговый файл: `public/og-gde-poest.jpg`, 1200×630, не WebP.

## 6. Перелинковка

### Откуда ставить ссылку на /gde-poest

**Рекомендация: нигде в постоянной навигации. Только в одном контекстном месте.**

Страница noindex и не является коммерческой точкой входа. Лишние входящие ссылки
от индексируемых страниц не дают SEO-выгоды (ссылка noindex не передаёт вес),
зато размывают краулинговый бюджет.

Единственное оправданное место — `/services`, раздел «В нашем комплексе»
или в блоке инфраструктуры: одна строка «Кофейня „Эндорфин" — прямо в комплексе,
скидка 5% для гостей» с ссылкой на /gde-poest.
Логика: гость читает про сервис, интересуется кофейней, переходит за деталями.

**Из /apartments — нет.** /apartments — главная коммерческая страница,
каждая дополнительная ссылка от неё снижает «вес», направленный в ключевые разделы.

**Из футера — нет.** Футер содержит карту коммерческих разделов.
Утилита для гостей туда не относится.

**Из главной — нет.** Главная передаёт вес на /apartments, /professorskiy-ugolok,
/zhile-s-basseynom. Не размываем.

### Что ставить внутри /gde-poest

- Ссылка на /apartments («Забронировать апартаменты»).
- Телефон отеля (кликабельный tel:).
- Ссылки на чужие заведения — external, `rel="nofollow noopener"`,
  так как это рекламные/партнёрские упоминания, а не редакционные ссылки.

## 7. Sitemap

Страница noindex — в sitemap.ts не добавляем.

Правило: URL с `robots: { index: false }` в sitemap создаёт противоречие
(sitemap приглашает к индексации, robots запрещает). Яндекс и Google трактуют
это по-разному, но в обоих случаях это либо бесполезно, либо мешает.
Noindex-страницам в sitemap не место.

Если в будущем будет принято решение индексировать /gde-poest,
добавить в `app/sitemap.ts` следующий фрагмент (вставить в массив `staticPages`):

```typescript
{
  /*
   * Информационная страница-гид для гостей.
   * Кластер «где поесть алушта» — проверить частотность в Вордстате
   * перед включением (должно быть >500 показов в кластере).
   */
  url: `${baseUrl}/gde-poest`,
  lastModified: new Date('2026-10-10'),
  changeFrequency: 'monthly' as const,
  priority: 0.4,
},
```

Приоритет 0.4 — ниже /privacy (0.2 только у техстраниц) и ниже всех коммерческих.
Информационная страница без прямой конверсии не заслуживает более высокого сигнала.

## 8. Открытые вопросы

- Частотность кластера «где поесть алушта» не снята. Если Олег откроет Playwright
  с авторизованным Вордстатом — стоит снять для записи, чтобы иметь цифру
  при следующем пересмотре решения об индексировании.
- Кофейня «Эндорфин» упоминается только как партнёр по скидке. Если у неё появится
  официальный сайт — поменять ссылку с Яндекс.Карт на официальный URL.
- Страница /services: добавление одной строки про «Эндорфин» со ссылкой на /gde-poest
  требует отдельного тикета для фронтенда.
