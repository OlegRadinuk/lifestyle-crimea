# Спецификация: переработка детальной страницы апартамента `/apartments/[id]`

> Статус: готово к разработке  
> Файлы: `app/apartments/[id]/ApartmentHero.tsx`, `app/apartments/[id]/apartment.css`  
> Дата: 2026-08-26

---

## Корневая проблема

`.apartment-hero` имеет `height: 100dvh; overflow: hidden` — на десктопе и мобиле.
Страница физически равна одному экрану. Всё, что не влезло в первый экран, недоступно.

**Решение:** сделать `.apartment-hero` первым экраном фиксированной высоты, а после него дать странице нормально скроллиться. Документ (body/html) должен скроллиться — не внутренний контейнер.

---

## Архитектурное решение

### Что меняется

Страница делится на две части:

**Часть 1 — Hero-экран** (остаётся как сейчас, только меняется высота):
- `.apartment-hero` получает `height: 100svh` (вместо `100dvh`) и `overflow: hidden`
- Вся текущая вёрстка внутри не трогается

**Часть 2 — Content-секции** (новые, под Hero):
- Рендерятся после `</section>` ApartmentHero в `ClientApartmentWrapper` или родительском компоненте
- Обычный документный поток, страница скроллится штатно

### Почему `100svh` вместо `100dvh`

`100dvh` на мобиле "прыгает" при прокрутке из-за появления/исчезновения адресной строки браузера. `100svh` (small viewport height) — стабильное значение, равное минимальной высоте вьюпорта с видимой адресной строкой. Первый экран всегда умещается без скролла.


## Детали каждой секции

### Hero-экран (изменения минимальны)

**CSS-правки в `apartment.css`:**

```css
/* БЫЛО */
.apartment-hero {
  height: 100dvh;
  overflow: hidden;
}

/* СТАЛО */
.apartment-hero {
  height: 100svh;
  overflow: hidden;
}

/* Мобильная ветка — то же самое */
@media (max-width: 768px) {
  .apartment-hero.mobile {
    height: 100svh; /* было: height: 100vh */
    overflow: hidden;
  }
}
```

Больше в Hero ничего не трогать. Все панели, фото, тайминг, анимации — без изменений.

**Мобиль: убрать кнопку «Читать полностью»**

Кнопка была временной заплаткой для описания, зажатого в первом экране. После переноса описания в отдельную секцию кнопка и `descExpanded`-стейт становятся ненужными. Убрать из JSX:

- `const [descExpanded, setDescExpanded] = useState(false)` — удалить
- Блок `<div className={apartment-info-description${descExpanded ? ' is-expanded' : ''}>` — заменить на `<div className="apartment-info-description is-expanded">` (всегда раскрыто) ИЛИ убрать описание из мобильного Hero совсем (см. ниже)

**Рекомендация для мобильного Hero:** в `.apartment-info-mobile` оставить только:
- eyebrow, название, мета (гости, площадь)
- feature-chips (первые 3)
- apt-timeline-horizontal (навигация по фото)

Описание убрать из Hero — оно появится в секции ниже. Это освободит место на маленьком экране и уберёт проблему с overflow.

**Подсказка про галерею на мобиле (решение: только счётчик).**

Владелец жаловался, что на мобиле неочевидно, что фото можно листать и открыть на весь экран. Выбрано одно решение — счётчик «3 / 12» поверх фото:

- Добавить в мобильный Hero поверх слайдера (z-index выше оверлея, но ниже `.apartment-info-mobile`) бейдж с текстом `{activeIndex + 1} / {apartment.images.length}`
- Позиция: правый верхний угол, `top: 72px; right: 16px` (ниже хедера)
- Стиль: `background: rgba(0,0,0,0.45); backdrop-filter: blur(6px); border-radius: 20px; padding: 4px 12px; font-size: 13px; color: #fff; letter-spacing: 0.05em`
- На десктопе этот бейдж не нужен — там уже есть нумерованная навигация в `.apt-photo-nav`
- Иконку лупы и плёнку превью НЕ добавлять — это городит лишнее

### Section: Описание

**Назначение:** гость читает полный текст апартамента; абзацы сохраняются как их написал менеджер.

**Layout:**
- Desktop (≥1024px): контейнер max-width 900px, центрирован, `padding: 80px 40px 60px`
- Tablet (768–1023px): `padding: 60px 32px`
- Mobile (<768px): `padding: 48px 20px`

**Контент:**
- Заголовок секции: `<h2>` «Об апартаменте», `font-size: clamp(22px, 3vw, 32px)`, цвет `#139AB6`
- Текст: `renderDescription(apartment.description)` — функция уже есть в компоненте, использовать её. Абзацы через `<p>`, переносы через `<br>`. Стиль текста: `font-size: 16px; line-height: 1.75; color: #2c3a42`
- Никаких clamp, никакого overflow hidden — текст читается целиком
- Мета-строка над заголовком (мелко): «До N гостей · M м²» — дублировать из Hero, чтобы на мобиле было видно сразу при скролле

**Фон секции:** белый или `#f7fbfc` (чуть голубоватый, как бренд). Не тёмный — Hero тёмный, контраст нужен.

---

### Section: Особенности

**Назначение:** полный список удобств, видно всё сразу.

**Layout:** вытащить из Hero и перенести сюда. Грид `apt-features-grid` с его карточками `apt-feature-card` оставить как есть — они хорошо сделаны.

**Изменения:**
- Убрать из десктопного Hero блок `.apt-features-panel` (он занимает `grid-column: 1/-1` и вытесняет описание)
- Рендерить всё в отдельной секции ниже, без `max-height: 220px` и без кнопки «Все (38) →»
- Показывать все фичи сразу — не нужно скрывать, страница теперь скроллируется
- Заголовок секции: `<h2>` «Особенности», тот же стиль
- Фон: такой же как у Описания (чередование не нужно, они рядом)

**CSS что убрать:**
```css
/* Убрать ограничение высоты грида */
.apartment-hero .apt-features-grid {
  max-height: 220px; /* удалить */
  overflow: hidden;  /* удалить */
}
.apartment-hero .apt-features-grid.expanded {
  max-height: 460px; /* удалить */
}
```

### Section: CTA-блок

**Назначение:** финальный призыв забронировать, для тех кто дочитал до конца.

**Контент:**
- Заголовок: «Готовы забронировать?»
- Подпись: название апартамента + «от {priceBase} ₽/ночь» (если цена есть)
- Кнопка: та же «Проверить доступность» что в хедере — открывает тот же поповер-календарь
- Фон: тёмный (`#0a121a`) или градиент бренда — контраст с белыми секциями выше

## Порядок секций — логика продажи

1. **Hero (первый экран)** — эмоция. Вид на море, название. Человек понял «хочу сюда».
2. **Описание** — рациональный аргумент. Что за место, атмосфера, особенности локации. Менеджер вложил сюда продающий текст, его надо читать.
3. **Особенности** — снятие возражений. «А есть ли кондиционер / парковка / посудомойка?» — гость проверяет список.
4. **Панорама 360°** — «экскурсия» для неуверенных. Помогает тем, кто ещё колеблется.
5. **Отзывы** — социальное доказательство. Подтверждает, что у других было хорошо.
6. **CTA-блок** — действие. После того как прочёл, убедился, посмотрел — кнопка бронирования.

## Риски и что не трогать

### 1. Поповер календаря — НЕ ТРОГАТЬ

В `globals.css` в конце висит правило для `.header__calendar-popover` с `position: fixed`, которое обсчитывается от `.header` (у него стоит `transform`). Это сделано специально. Переработка Hero не касается хедера — риска нет, если фронтенд не переносит хедер или не меняет его `transform`.

### 2. Лайтбокс — ВНИМАНИЕ

Лайтбокс при открытии делает `body { position: fixed; top: -scrollY }` и при закрытии восстанавливает позицию. Это работает с документным скроллом. После переработки документный скролл останется — лайтбокс должен продолжить работать без изменений.

**Критично:** НЕ создавать собственный scroll-контейнер (`overflow-y: auto` на wrapper-дивах уровня страницы). Скролл — только на `body`/`html`. Если появится вложенный скролл-контейнер, `scrollY` будет возвращать 0 при открытом лайтбоксе, и страница будет прыгать наверх при закрытии.

### 3. Раздельные JSX-ветки desktop/mobile

В `ApartmentHero.tsx` две ветки: `if (!isMobile) { return <section class="desktop">... }` и ниже мобильная. Новые секции (Описание, Особенности, CTA) рендерить **вне** `ApartmentHero.tsx` — в обёртке `ClientApartmentWrapper` или `page.tsx`. Так обе ветки Hero не трогаются, а новый контент общий для всех ширин.

### 4. `renderDescription` — не копировать

Функция `renderDescription` живёт внутри `ApartmentHero.tsx`. Для использования в новой секции Описания — либо вынести её в отдельный утилитный файл `app/apartments/[id]/renderDescription.ts` и импортировать в обоих местах, либо продублировать логику (она простая: `text.split(/\n\n+/)` → `<p>`, `split('\n')` → `<br>`). Дублирование хуже — выносить.

### 5. CSS-скоп

Все правила в `apartment.css` завёрнуты в `.apartment-hero { ... }`. Новые секции нужно стилизовать либо в отдельном файле `apartment-content.css`, либо через Tailwind-классы на уровне разметки. Нельзя добавлять правила вне `.apartment-hero` в `apartment.css` — это опасно (комментарий в первой строке файла об этом предупреждает).
