## 2. Главный факт: аналитики на сайте НЕТ

Проверено 28.08 и в коде, и в отдаваемом HTML прода:

```
Яндекс.Метрика     не найдена ни в коде, ни на странице
Google Analytics   не найден
GTM                не найден
cookie-баннер       ЕСТЬ и говорит про аналитику — а счётчика нет
Search Console      подключён, данные отдаёт
```

То есть «Метрика настроена криво» — неверно. Её **нет совсем**. Значит:

- нет ни одной цели, нет данных о конверсиях;
- Директ нельзя вести по конверсиям — только по кликам, вслепую;
- ретаргетинг и look-alike строить не на чем;
- нельзя ответить на вопрос «сколько стоит бронь».

**Это блокер номер один.** Пока счётчика нет, любые кампании — трата бюджета
без обратной связи.

## 4. Что по SEO уже сделано (не переоткрывать)

**Июль 2026:**
- метаданные каталога переписаны под Wordstat: ведём «жильём», не
  «апартаментами» («снять жильё в Алуште» — 3 389/мес против 212 у
  «снять апартаменты в Алуште», регион Россия, июль 2026);
- у карточек title по формуле «Апартаменты {вид} в Алуште, {площадь} м² — {имя}»;
- цена в сниппете берётся из действующего сезона, а не из базовой ставки;
- og-image починен (был WebP, превью приходили пустыми).

**Август 2026:**
- своё og-превью для каждого апартамента: `/api/og/<id>` режет первый кадр в
  JPEG 1200×630 (webp в превью не показывают ни Telegram, ни WhatsApp, ни VK);
- человеческие адреса: `/apartments/deep-forest` вместо
  `/apartments/8b577381-4cf1-450b-ac43-54b8a0edcc59`. 47 слагов, коллизий нет.
  Старые адреса продолжают работать, canonical и og:url ведут на короткий;
- убраны пустые `?checkIn=&checkOut=&guests=2` из ссылок каталога;
- страница апартамента переведена на живой рендер (была ISR на сутки — правки
  менеджера появлялись на сайте только через сутки);
- страница апартамента научилась прокручиваться, описание читается целиком
  (раньше первый экран обрезал текст: из 828px было видно 59px);
- sitemap: 58 URL, robots.txt закрывает /admin, /api, /_next.

⚠️ Незакрытый хвост: 301-редиректа со старого адреса на новый **нет** —
`permanentRedirect` в этой сборке Next отдаёт 200. Дубли склеиваются только
через canonical.

## 5. Директ: что есть и чего нет

```
инфраструктура   MCP-сервер Яндекс.Директ API v5 — D:\projects\yandex-direct-mcp
скилл            .claude/skills/direct (20 инструментов)
проверка токена  node ~/.claude/skills/direct/tools/check-token.mjs
переменная       YDIRECT_TOKEN  — НЕ ЗАПОЛНЕНА
```

**Кампании раньше крутили** (со слов владельца), настраивал не он. Доступа в
старый кабинет у нас нет, что именно откручивали и с каким результатом —
неизвестно. Это надо поднять до запуска, чтобы не купить те же гипотезы дважды.

Порядок получения доступа к API:
1. логин с правами на кабинет Директа;
2. OAuth-приложение на oauth.yandex.ru → ClientID + Client Secret, право
   «использование API Яндекс.Директа»;
3. заявка на доступ к API в кабинете (рассматривают несколько рабочих дней);
4. до одобрения работает **песочница** — структуру кампаний можно собрать и
   отладить уже сейчас;
5. токен живёт ~год, кладётся в `YDIRECT_TOKEN`.

**Через браузер Директ вести не будем**: капчи, двухфакторка, ломкие селекторы,
а главное — это деньги клиента, молчаливая ошибка скрипта стоит бюджета.

## 6. Юридический блокер по ретаргетингу

Владелица просит «настроить ретаргетинг на базу контактов» — то есть залить
телефоны и почты гостей в Яндекс.Аудитории и крутить на них рекламу + look-alike.

Механика рабочая, но: **чекбокс в форме брони даёт согласие на обработку данных
для брони, а не на рекламу и не на передачу третьим лицам.** Для загрузки базы в
Яндекс нужно отдельное основание, иначе это 152-ФЗ. Формулировку надо добавить в
форму и политику ДО запуска.

## 7. Что нужно сделать

**Первое — Метрика.** Поставить счётчик, привязать к Вебмастеру и Директу,
завести цели: заявка посуточная, заявка на долгосрок, клик по телефону,
открытие календаря. Учесть: cookie-баннер уже есть, счётчик должен грузиться
после согласия.

**Второе — Яндекс, а не Google.** Весь отчёт выше — гугловый, а в Крыму
основной трафик в Яндексе. Нужен доступ в Яндекс.Вебмастер: индексация,
позиции, запросы. Без этого мы смотрим не туда.

**Третье — семантика и посадки.** Собрать ядро по Wordstat под Алушту
(«снять квартиру посуточно Алушта», «жильё у моря Алушта», «апартаменты
Профессорский уголок», долгосрок отдельным кластером — под него уже есть
посадка). Решить, какими страницами закрывать кластеры: сейчас весь трафик
тянет главная, карточки не участвуют.

**Четвёртое — структура кампаний на 20к/мес.** Поиск + РСЯ, разделение по
интенту (посуточно / долгосрок / бренд-защита), минус-слова, UTM, стратегия
назначения ставок. Собрать в песочнице, перенести после токена.

**Пятое — бренд-защита.** Понять, кто стоит выше по «стиль жизни алушта» и
почему, и вернуть себе первое место по собственному названию.

## 8. Чего мы не знаем (честно)

- Позиции и запросы в **Яндексе** — доступа в Вебмастер нет.
- Что крутили в Директе раньше, какой был CPA и были ли конверсии.
- Сколько стоит бронь и какая доля броней приходит с сайта, а не с
  Travelline/агрегаторов — без Метрики это не считается.
- Кто перебивает бренд в выдаче.
- Сезонность спроса по своим данным (только общие соображения про Крым).
